Training a custom object detection model is more than simply clicking a **Train** button. Before the model can learn anything, it needs a dataset containing the exact objects you want it to detect. In my case, I wanted to detect vehicle license plates, so I first collected and annotated a dataset using [Roboflow](https://roboflow.com/), exported it in YOLO format, and then trained it with [Ultralytics YOLO](https://docs.ultralytics.com/).

---

## Reading the Training Logs

One of my favorite parts of training is watching the logs in real time. They show exactly what the model is doing, which hardware is being used, how many images are in the dataset, GPU memory consumption, current losses, and the progress of every epoch.

![YOLO training output](/articles/img/yolo-training.png)

The log above shows a real training session. Besides displaying the model architecture, it also reports the CUDA device, GPU memory usage, image size, optimizer configuration, dataset statistics, and the current training progress. It's a quick way to confirm everything is running correctly before waiting for the training to finish.

## Building the Dataset

A model is only as good as the data it's trained on. Every image needs to be annotated with bounding boxes so YOLO knows exactly where each object is located.

After finishing the annotations, I exported the dataset in YOLO format, which generates a `data.yaml` file containing the dataset structure and the paths for the training, validation, and test images.

---

## Choosing a YOLO Model

Ultralytics provides several versions of the same architecture, each optimized for a different balance between speed and accuracy.

| Model | Speed | Accuracy |
| ------ | ----- | -------- |
| YOLOv8n | Fastest | Lower |
| YOLOv8s | Fast | Better |
| YOLOv8m | Balanced | High |
| YOLOv8l | Slower | Higher |
| YOLOv8x | Slowest | Highest |

For my training I chose **YOLOv8n** because it's the lightest version. It trains much faster, requires less GPU memory, and is perfect for experimenting before moving to larger models.

## Starting the Training

Once the dataset was ready, starting the training only required loading the base model and calling the `train()` function.

```python
from ultralytics import YOLO

model = YOLO("yolov8n.pt")

results = model.train(
    data="/content/license/data.yaml",
    epochs=100,
    imgsz=640,
    project="/content/drive/MyDrive/YOLO_Treinos",
    name="meu_treino_placas"
)
```

## The dataset structure will look like this:

```text
dataset/
├── train/
│   ├── images/
│   └── labels/
├── valid/
│   ├── images/
│   └── labels/
└── data.yaml
```

Some parameters are worth understanding:

- **epochs** determines how many times the model will see the entire dataset.
- **imgsz** defines the input image resolution.
- **project** is where every training run will be saved.
- **name** creates a separate folder for that specific experiment.

Changing these values makes it easy to organize multiple experiments without overwriting previous results.

---

## Understanding the Output Files

Every training session creates several files, but two of them are especially important.

```text
weights/
├── best.pt
└── last.pt
```

The **best.pt** file stores the model that achieved the best validation performance during training. This is usually the file you'll use later for inference.

The **last.pt** file stores the latest checkpoint. Even if the model hasn't improved recently, it contains the most recent training state and can be used to continue training later.

---

## Continuing a Previous Training

Sometimes 100 epochs aren't enough. Instead of starting over, Ultralytics allows the training to continue exactly where it stopped.

```python
from ultralytics import YOLO

model = YOLO(
    "/content/drive/MyDrive/YOLO/license_plate_100epochs/weights/last.pt"
)

results = model.train(
    data="/content/license/data.yaml",
    resume=True
)
```

Using `resume=True`, the optimizer state, learning rate schedule, and model weights are restored automatically. Training continues from the last completed epoch instead of restarting from zero.

---

## Hardware Makes a Huge Difference

Training deep learning models is one of the most demanding parts of computer vision. A dedicated GPU can reduce training time from hours to a fraction of that.

During my experiments I trained the model using an NVIDIA Tesla T4 GPU, which provided enough memory to train with a batch size of 16 and 640×640 images without memory issues.

Although it's possible to train YOLO on a CPU, the process becomes significantly slower. For larger datasets or models like YOLOv8l and YOLOv8x, a capable GPU quickly becomes a necessity rather than a luxury.

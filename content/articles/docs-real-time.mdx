When I first thought about controlling a game with body movement, I immediately assumed I'd need some kind of AI model.

After experimenting with OpenCV, I realized I didn't.

---

## Detecting Motion

The core idea is simple.

Every frame captured by the webcam is compared with the previous one. If enough pixels change inside a specific area, I consider that movement has occurred.

Instead of recognizing a person, the application only cares whether something moved.

![Motion Detection](/articles/img/right.png)

![Motion Detection](/articles/img/left.png)

To reduce noise, each frame goes through a few preprocessing steps before the comparison.

---

## Creating Detection Areas

One decision I made early on was avoiding hardcoded controls.

Instead, I created configurable regions of interest (ROIs) that can be placed anywhere on the camera feed.

For example:

- Left square → `A`
- Right square → `D`
- Upper square → `Space`

Whenever movement exceeds the configured threshold inside one of these regions, the corresponding key is pressed automatically.

---

## Triggering Keyboard Inputs

After detecting movement, the application simply simulates keyboard events.

The implementation is surprisingly small.

```cpp
if (motion > threshold)
{
    keybd_event(key, 0, 0, 0);
}
else
{
    keybd_event(key, 0, KEYEVENTF_KEYUP, 0);
}
```

The challenge wasn't pressing keys.

The difficult part was finding thresholds that felt responsive without constantly triggering false positives.

---

## Saving the Configuration

Recreating every detection square after restarting the application quickly became frustrating.

To solve that, I added a configuration file that stores each ROI together with its keyboard binding.

The next time the application starts, everything is restored automatically.

That made experimenting with different layouts much more practical.

---

## Measuring a Jump

Simple movement detection worked well for directional controls, but jumping required a different approach.

Instead of looking inside a square, I placed a horizontal line on the screen.

Whenever the player crossed that line, the application started measuring how long they stayed above it.

![Jump Detection](/articles/img/jump-line.png)

The measured airtime could then be used to estimate jump strength or trigger different actions depending on how long the player remained in the air.

---

## Why I Chose OpenCV

OpenCV already provides everything needed for this kind of project.

There was no need for object detection, pose estimation, or deep learning models.

Using basic image processing techniques kept the application lightweight while still being responsive enough for real-time interaction.

For this use case, simplicity turned out to be the better solution.

---

## What Took the Most Time

Writing the motion detection algorithm wasn't actually the hardest part.

Most of the development time went into tuning thresholds, reducing camera noise, and making the controls feel natural.

Small changes in lighting, webcam position, or room conditions could completely change the behavior of the system.

Making those adjustments taught me that building a real-time computer vision application often involves much more experimentation than writing complex algorithms.

---
title: "How PID Keeps the Robot on the Line"
date: 2026-01-22
---

When I first started building my line follower, I thought the hard part would be making the robot detect the line. It turned out that reading the sensors was actually the easy part.

The real challenge was keeping the robot centered while moving at a reasonable speed. That's where PID control made all the difference.

---

## From Sensors to Movement

Every loop starts by reading the infrared sensors. Based on which sensors detect the line, I calculate an error that tells the robot how far it is from the center.

For example:

```text
10000 → -2
11000 → -1
00100 →  0
00011 → +2
```

A negative value means the robot is drifting to the left, while a positive value means it's moving to the right.

This error becomes the input for the PID controller.

---

## The PID Formula

The controller itself is surprisingly simple.

```cpp
integral += error;
derivative = error - previousError;

pid = (Kp * error)
    + (Ki * integral)
    + (Kd * derivative);

previousError = error;
```

Each part has a different job.

- **Kp** reacts to the current error.
- **Ki** compensates for accumulated error over time.
- **Kd** predicts the movement and smooths the correction.

Even though the formula is short, changing one parameter completely changes how the robot behaves.

---

## Turning the Robot

The PID output isn't sent directly to the motors.

Instead, I use it to adjust the speed of each wheel independently.

```cpp
leftSpeed  = baseSpeed + pid;
rightSpeed = baseSpeed - pid;
```

If the robot starts drifting left, the controller speeds up one motor while slowing down the other. This differential steering naturally brings the robot back to the center of the line.

---

## Finding Good PID Values

Writing the PID controller only took a few minutes.

Finding values that actually worked took much longer.

I started by adjusting only the proportional gain until the robot could roughly follow the line. After that, I introduced the derivative term to reduce oscillation during curves.

These were the values that produced the best results on my robot.

```cpp
Kp = 18.0;
Ki = 0.0;
Kd = 9.0;

baseSpeed = 130;
```

Notice that the integral gain remained at zero. During my tests, adding an integral component didn't improve the behavior, so I decided to keep the controller simpler.

---

One thing I learned is that even tiny parameter changes can completely alter the robot's behavior.

Too much derivative made every correction feel delayed.

Increasing the base speed without retuning the controller often caused the robot to overshoot corners and lose the line.
